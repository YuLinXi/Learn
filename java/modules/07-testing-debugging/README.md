## 小任务顺序

1. 选已有字典接口，说明单元测试、Web 层测试、数据库集成验证各证明什么、遗漏什么；补当前真正缺少的一项。
2. 用断点和异常栈跟一个请求；把现象、输入、配置、调用和数据变化对应起来。
3. **现有故障验收**：教师在学习者已有字典/销售工程的副本中准备一处小故障或变更，只给业务现象和预期，不提前说明文件/原因。准备时保留原工程；本轮课程建设不预植故障或预写答案。
4. 学习者自己复现，提出假设并收集证据，做最小修改，验证故障消失和原有行为保持。若接受关键提示，换另一小变式复验；不是追加大型陌生项目。
5. 对照公司测试：解释候选不存在、唯一、多个时的预期和哪些对象不应初始化。未运行测试只能记为已读并解释预期。

## 本轮验收

- [ ] 提供修改前可复现现象与定位依据，不靠教师直接给出位置。
- [ ] 修改只针对问题，并有失败→修复和回归证据。
- [ ] 能说明 mock 的边界；数据库约束、事务和网络行为由相应真实验证支持。
- [ ] 能读异常栈并找到与业务现象有关的首个原因，说明已排除与未排除的假设。
- [ ] 帮助程度与独立新变式有记录。
