## 小任务顺序

1. 在销售查询练习旁增加一个局部实验，以可控任务和同步信号验证并发上限；不依赖随机 sleep 恰好重现。
2. 注入任务异常、等待超时和中断，核对许可/资源被正确释放。区分等待超时、取消请求与底层工作实际停止。
3. 在本地缓存实验中用两个租户、相同查询条件验证隔离，再解释数据变更后的失效规则；先明确规则再实现。
4. 阅读一个公司跨线程或 RPC 边界，标出调用者、执行者、超时/错误传播和当前不可见实现。ThreadLocal 上下文跨线程与清理只在该例涉及时补。

## 本轮验收

- [ ] 能复现共享状态或并发控制问题，并用确定条件验证修正。
- [ ] 异常、超时、中断后的上限与资源状态正确，不因失败泄漏许可。
- [ ] 本地缓存隔离与失效符合明确契约，能解释 key 设计。
- [ ] 能区分本地实验、RPC 调用契约与真实分布式验证；公司运行仍单列。

第一轮中间件达到职责与调用边界阅读深度；真实部署由后续具体任务触发。本地模拟不记为 Redis/Dubbo 集成通过。
