# M03 · Maven 与公司工程导航

前置：M01；可与 M02 交叉。目标是从“能运行骨架”进到“自己搭建并解释工程”。

## 定向阅读

[R01 第 15 章与 R03](../../RESOURCES.md)：坐标、目录、生命周期、依赖范围、传递依赖、父 POM、dependencyManagement、聚合模块。按当前问题查官方文档。

公司基线与导航见 [源码地图](../../PROJECT-STACK.md)。先查仓库规则，再读 udc、udc-parent、cdp-report 的 POM；boot-extend 仅作为扩展工程对照。

## 小任务顺序

1. 在 practice/work/ 的新目录从空文件创建基础 Maven 工程，自己配置源码和测试目录、Java release、JUnit 与插件；对照起始工程检查即可，不直接复制后宣称独立创建。
2. 运行单个测试和 package；解释源码、测试、target 产物与依赖之间的关系。
3. 在自己的工程执行 dependency:tree、help:effective-pom，回答一个依赖版本或 scope 问题。第一次解析插件可能需要网络，环境失败单列。
4. 查公司聚合模块与继承路径，区分“模块依赖图”和“HTTP 调用链”。定位启动类、装配模块、配置文件名及 profile 来源，不复制内部配置值。
5. 在一份工程图里标明已知依赖与缺失父工程；本阶段只定位启动/配置，M04 再解释 Bean 机制。

## 本轮验收

- [ ] 独立重建小工程并运行测试，能解释 compile/test/package 和测试依赖。
- [ ] 说明聚合与继承的区别，找到一个受版本管理影响的依赖。
- [ ] 给出 UDC/CDP 主要模块关系、启动入口与配置位置；引用当前 test 提交。
- [ ] 明确公司 boot 版本不是 Spring Boot 版本，父依赖不可见时保持版本未知。

公司构建不作为本轮通过条件。仅凭自己工程能构建不能给公司构建打通过。
