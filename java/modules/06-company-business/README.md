# M06 · 公司业务分层与权限

前置：M05。本轮先读 UDC 创建与 CDP 前台运行，复杂发布和完整预览矩阵留给 M09。

## 材料

以 [源码地图](../../PROJECT-STACK.md) 的 UDC/CDP 业务链路为入口；实际阅读前遵守公司仓库上下文规则。遇到注解、事务或代理问题回查 [R05](../../RESOURCES.md)。

## 小任务顺序

1. 从 UdcEnumCategoryController.create 出发，自行定位接口、DTO、AppService 实现、领域服务和 DAO，说明每层输入、输出和职责。接口/DTO 在 udc-biz，不从 facade 名字猜路径。
2. 标出事务、操作权限、业务校验与日志；读 UdcAppOpsFilter 的可见处理。基础框架注册和拦截先后缺证据时保留未知。
3. 将 [字典 D3](../../practice/DICTIONARY.md) 的身份/租户/应用规则加入自己的工程，用允许、拒绝、跨租户场景验证。身份来自服务端测试上下文，不信任客户端自报租户。
4. 跟 CDP 前台运行：Controller → AppService → prepareSaved → Executor → Gateway → QueryEngine。区分资源授权、数据集可用性/使用权限、数据行权限。
5. 对正常结果、内容状态短路、数据行权限导致的结构化空结果各给一个源码推演。分开说明元数据读取、进入引擎和目标业务查询，不能从短路推断全程无数据库访问。

## 本轮验收

- [ ] 在不逐文件带路的情况下定位两条基本路径，引用提交、符号与职责。
- [ ] 区分声明、可见实现和运行效果；明确至少一处证据边界。
- [ ] 字典权限练习确实覆盖同租户允许、无授权拒绝、跨租户访问。
- [ ] 解释 CDP 三类结果的区别，以及发生在哪一层。
- [ ] 给一个小字段或规则变化，指出可能改动与需补的验证。

本地权限练习的通过不等于验证公司权限框架。公司运行单列待验；模块通过仅覆盖声明的可见源码与独立能力。
