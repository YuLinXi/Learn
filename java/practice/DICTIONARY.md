# 贯穿练习 A · 应用字典

这是合成业务契约，不宣称与公司所有接口一致。先 M01 对象、M04 内存接口，再 M05 持久化、M06 权限、M07 故障定位。公司创建/删除链路用于比较机制，不复制完整业务实现。

## 统一业务规则

- Category：`id`、`appId`、`code`、`name`。内部 id/appId 可使用 Long，接口中均作为十进制字符串表达，覆盖超过 JavaScript 安全整数范围的 ID。
- `appId` 是正整数；创建时 code/name 必填，缺失或 null 均非法。code 仅小写 ASCII 字母、数字和下划线，长度 1–32；name 去除首尾空白后长度 1–50。空白名称非法。
- 同一应用下 code 唯一；到 M06 再将唯一性和访问范围扩展为租户+应用。同一 code 的重试创建返回冲突，不静默覆盖。
- 更新只修改 name，code 保持不变。找不到分类返回不存在。
- 列表按 id 升序；page 从 1 开始，size 默认 20、范围 1–100；无匹配返回空列表和 total=0。缺省 page/size 使用默认值，显式非法值返回校验失败。

## D1 · M04 内存接口

基础路径：`/api/apps/{appId}/categories`。

| 操作 | 输入 | 预期 |
|---|---|---|
| POST 基础路径 | code/name | 成功 201，返回分类；非法 400，重复 409 |
| GET 基础路径 | page/size | 200，`items`、`total`、`page`、`size` |
| GET /{id} | 路径 id | 成功 200，不存在 404 |
| PUT /{id} | name | 成功 200；非法 400，不存在 404 |
| DELETE /{id} | 路径 id | 成功 204 且无响应体，不存在 404 |

错误响应固定包含 `code` 和 `message`，不返回堆栈。M04 不引入登录系统，应用 ID 只是路由业务参数，真实权限在 D3 加入。

JSON 必验两项：`9007199254740993` 作为 ID 字符串完整往返；创建名称缺失、null、空白分别符合规则。金额和日期不为凑清单额外加入字典 DTO。

最小正常创建例：appId 为字符串 `"101"`，code 为 `"priority"`，name 为 `"优先级"`。ID 由服务生成；具体起始值由练习说明，不把硬编码常量作为验收条件。

## D2 · M05 数据与事务

将同一业务改为 MySQL/MyBatis 存储，保留已有 HTTP 契约。分类表保留唯一业务键；新增子项表，字段至少包括 categoryId、code、name，分类内子项 code 唯一。

扩展创建支持可选 items 数组：缺省表示空数组，显式 null 非法；每项遵循 code/name 规则。分类与其所有子项在同一事务创建。用后续子项重复 code 的约束失败验证回滚，检查分类和先前子项均未留下；避免只验证抛出异常而不检查数据库。

本地删除可在一个服务事务中删除分类和子项；公司通过事件衔接的路径在 M09 阅读，两者机制和证据分别说明。

## D3 · M06 权限与隔离

使用明确的服务端测试身份上下文，不实现完整登录平台。上下文至少包含 userId、tenantId 与允许访问的应用；租户不取自客户端自报字段。

| 场景 | 预期 |
|---|---|
| 租户 A 用户获准访问应用 101，访问自己的分类 | 允许 |
| 租户 A 用户未获准访问应用 102 | 403 |
| 租户 B 用户提交租户 A 的分类 ID | 当前范围内不可见，404 |
| 不同租户使用相同 appId/code | 各自独立，不互相覆盖或返回数据 |

客户端无法借修改 path/body 改变服务端租户上下文。此表是练习契约，公司的拒绝状态和权限机制由实际源码另行确认。

## D4 · M07 维护任务

教师从已有工程选一处小故障或变更，只给业务现象与期望。学习者提供修改前复现、定位依据、最小修改、原有行为回归；接受关键提示后换新变式复验。它替换本模块既有故障任务，不新增大项目。
