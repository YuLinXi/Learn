# 贯穿练习 B · 销售统计

合成数据见 [sales.csv](data/sales.csv)，业务期望见 [sales-expected.json](data/sales-expected.json)。一行代表一笔销售记录，数据 ID 唯一；金额以十进制精确数处理。这里给结果契约，不提供 Java 或 SQL 解法。

## 共同口径

- 基础筛选：tenant_id=A 且 status=PAID。CANCELLED、PENDING 和其他租户不参加计算。
- 金额=quantity × unit_price；数量 0 合法，金额为 0，该行仍计为一笔记录。金额输出两位小数。
- CSV 空 region 在 Java 中作为缺失值，在 SQL 中导入为 NULL；统计统一归为 UNKNOWN。空值不丢弃，也不与其他地区混合。
- 计数是筛选后的记录条数，不是数量合计；商品或地区重复属于不同销售记录，不能随意去重。
- 新变式中的负数量、负价格或非法金额按输入错误拒绝；不把它们静默转成 0。正常夹具本身没有这些非法记录。

## S2 · M05 SQL 与分页

在 MySQL 建表并导入同一业务数据。可以采用合适的 Java/SQL 表示，只要求业务语义一致；不要把字符串金额用于数值排序。

地区聚合结果按金额降序、region 代码升序排列：EAST、WEST、UNKNOWN。按地区分组结果分页，page=1/size=2 返回 EAST、WEST；page=2 返回 UNKNOWN。totalGroups=3；全体金额仍为 169.50，不能把当前页小计当成全局总额。

保留空结果时的约定：totalGroups=0、groups=[]、总金额=0.00。说明 SUM 在空集合上的数据库行为与 API 契约之间如何转换。

## S3 · M05 JOIN 基数

只在此阶段引入 [sale-tags.csv](data/sale-tags.csv)：1001 有 featured、campaign 两个标签。

在基础筛选上增加“至少有 featured 或 campaign 中任一标签”的条件，期望是 **1 笔、金额 20.00**。关联匹配次数不代表销售笔数。解释一种会错误得到 40.00 的写法，并自行修正；不通过任意去重掩盖其他正常重复销售。
