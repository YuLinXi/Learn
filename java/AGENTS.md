# Java 学习与接续规则

范围和验收以 [CURRICULUM.md](CURRICULUM.md) 为准；默认简洁中文，实践使用 Java。所有学习产物写在本空间，真实学习状态只从 [PROGRESS.md](PROGRESS.md) 及其证据恢复。

## 触发与接续

“开始/继续 Java 学习”、本空间学习语境的“继续/复习/汇报”触发下列流程；“定稿、完善细则、配置、调研”按准备任务执行，不启动学习会话或推进掌握。

1. 读取当前进度、它引用的学习记录、当前模块文件；未完成原题优先恢复。准备结束标志：能明确当前任务、已得证据和下一步。
2. 按 [复习接入](review/README.md) 使用 Java 专用 `start`。只登记和复习已有真实证据的知识；空队列直接接课。用户明确跳过时按工具流程处理；工具不可用则说明并接回课程，不推算成绩。
3. 开场只给“位置 / 本次只做 / 完成标志”，随后给一道复习题或完整恢复当前任务。未提供时间也先安排小步；用户指定任务或时间时缩小到相应范围。
4. 按模块入口诊断具体能力点，指定一段原文，再让用户解释或实现。独立正确可减免该点重复讲解；会解释但不会写则进入编码；环境失败记工程问题，不判概念失败。
5. 反馈后按 [通过规则](CURRICULUM.md#通过规则能力范围和证据) 验证。关键提示后的订正须用新情境独立复验；允许查文档，记录帮助程度。一个能力点可跨会话完成，不要求每次走完全部闭环。
6. 有真实作答、纠错、实践结果或用户结束学习时执行下节存档。准备起始工程、助手运行测试和笔记整理均不算用户通过。

## 存档与通过

写入前重新读取，完成后读回。仅更新本次有证据变化的内容：

1. 在 PROGRESS.md 保存实际位置、原题与输入、用户真实结果、已有提示、未完成部分和下一步一个动作。未答就写“未作答”；同一断点重复结束不重复追加记录。
2. 模块的阅读、独立练习、公司源码理解、公司运行分别记录。成绩用证据链接支撑；通过范围不得覆盖待验的公司实现。只有实际学习变化才更新学习日期，维护日期另记。
3. 重要理解或纠错按 [学习记录模板](templates/learning-record.md) 保存；同一问题优先增补原记录并保留修正缘由。仅讲解过的疑问保留待验，现有历史记录不因改课程而重写。
4. 有真实作答证据的独立知识点才执行复习 `register`；真实复习才 `answer`。背景、笔记、未学知识不登记。保留 PROGRESS.md 的工具生成复习段和 review/state.json 中未答原题。
5. 读回核对原题、结果、证据与下一步，告知保存位置；失败时说明未保存并给出恢复断点。记录字段按实际活动填写，不为填满模板增加任务。

## 阅读与实践

- 进入模块时只读取其列出的当前小节和必要参考；资料入口、版本差异见 [RESOURCES.md](RESOURCES.md)。读到新机制或版本冲突再核官方资料，不扩充整套并行课程。
- 复用 [两组练习](practice/README.md)。教学骨架在 practice/starters/，本人实现保存到 practice/work/；原始骨架与个人实现分别标识。运行、断言和环境记录使用 [练习模板](templates/exercise-report.md)。
- M01 先会运行，M03 再独立重建 Maven 工程；M04 引入 Web，M05 才引入数据库。准备骨架只提供启动与工具验证，不预填业务答案。
- 销售练习依据明确期望值验收。比较 Java/SQL 的业务语义，不只比较两边输出是否一致；公司测试阅读不视为测试执行。
- M07 从现有工程选一处未透露定位的故障或小变更，只给现象，要求复现、定位、最小修改和回归。替换已有验收任务，不追加陌生大项目。
- 公司阅读先遵守目标仓库 AGENTS.md/CONTEXT-MAP.md，再查 [源码地图](PROJECT-STACK.md)。按类和方法实际定位，不按仓库名推断接口所在位置。
- 每条链路标明“源码确认 / 调用契约推断 / 实现不可见 / 运行待验”。不根据注解、事件或 Future 的名字推断事务、同步性或执行时机。
- 源码基线见源码地图。用户要求更新 test 或当前任务涉及的符号已变化时，先检查分支、改动和提交，更新受影响引用；仅为续学不反复刷新所有仓库。依赖缺口见 [SOURCE-REQUESTS.md](SOURCE-REQUESTS.md)，补齐后只补未知环节。
- 本地练习使用合成数据；公司改动、连接服务或部署按实际工作任务处理，课程准备保持阅读边界。

## 章节笔记

触发：首次安排实际阅读、续学发现当前范围笔记缺失、核实错误/原文变化、用户要求整理。只处理本次范围，不是后台任务。

先读取原文和已有笔记，保存到 chapter-notes/<资料短名>/<章节短名>.md；同章持续增补。标明资料、版本、链接/源码提交和覆盖范围，提炼概念、机制、边界与必要例子；额外推论标“AI 补充”。材料不可读时标出缺口，不凭标题生成已核实内容。

完成标准：本次知识点有可定位来源，覆盖边界清楚，保存后读回。笔记与用户掌握证据独立，不改变进度。
