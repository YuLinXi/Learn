本课只练一个能力：判断模型输出的问题属于数据结构、事实错误，还是证据不足。这是让 Agent 结果可靠进入应用的第一步。

开始前

如果你还不熟悉 JSON，把这个信息告诉教师；如果熟悉，先试着回答：一段能够被程序解析的 JSON，为什么仍然可能给用户错误答案？

分清三个检查层次

程序能够解析 JSON，只说明语法可读。Schema 进一步约束字段和类型；符合 Schema 的内容，仍可能含有事实错误。对于支持的模型和 Schema，正确使用 Structured Outputs 可以约束输出结构；应用仍要处理拒绝、未完成响应等情况。

主要资料：OpenAI Structured Outputs。重点阅读 “Structured Outputs vs JSON mode” 与 “Handling mistakes”。

读数据时依次问：能解析吗？符合约定吗？有证据支持吗？

下面是教学用的简化契约：需要一个 city 字段，类型是字符串。假设任务要求提取“法国首都是巴黎”中的首都。

{ "city": "里昂" }

字段和类型满足契约，但与给定原文不符。这时需要检查提取结果和来源；重新包装 JSON 不能修正事实。

用三个反例练习

按题目已给的信息，选出可以确定的主要问题。先提交，再看反馈。

1 · 原文：法国首都是巴黎。输出：city = “里昂”。

2 · 契约要求 city 为字符串。输出：{ "city": 42 }。

3 · 契约要求 employees 为数值。输出 27，未提供人数来源。

迁移到你的应用

假设应用把用户的一句话提取成日程：{ "date": "2026-10-20", "title": "讨论" }。请举一个“结构满足约定，但业务上仍不能直接创建日程”的情况，并说明还需要检查什么。

把三题答案和这道迁移题的解释发回聊天。教师会据此判断这个知识点是否掌握，记录困难并选择下一节；本课不代表整个 M01 已通过。
