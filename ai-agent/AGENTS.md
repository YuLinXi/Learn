# AI Agent 学习接续规则

本目录是用户指定的学习空间，所有学习产物只写到此目录。采用“原始资料阅读 → 阶段汇报 → 诊断与巩固”。默认简洁中文，技术术语保留英文；实践使用 TypeScript / Node.js，Python 用于读懂教材示例。

## 开始或继续学习

1. 读取 README.md 中的学习目标、PROGRESS.md 和相关 learning-records，恢复当前阅读阶段、已知基础、待解决问题与复习项。
2. 读取当前 modules/*/README.md 与 RESOURCES.md，按课程大纲确定下一组小目标。已有能力根据用户陈述和诊断证据调整。
3. 为当前阶段指定可观察的目标、原始资料链接与精确阅读范围，区分必读和选读，说明阅读深度、阶段结束条件与汇报要求。开始后续模块前再核对具体小节与接口版本，不把资料入口当成已核对的阅读任务。按下文“章节知识点笔记”规则检查并整理本次范围的笔记，在阅读安排中提供笔记链接。
4. 用户自主阅读，学习期间可以随时提问。按问题解读原文、提供例子或协助调试；答疑围绕当前问题展开，阶段推进根据汇报与诊断决定。
5. 在阶段结束、用户主动汇报或卡点阻碍后续时进行诊断。根据用户读过的范围，用闭卷解释、反例、迁移题或小练习检查理解，再决定补读、复习或进入下一阶段。
6. 根据实际汇报与作答更新 PROGRESS.md，明确下一次何时回来汇报。阶段检查点由学习里程碑触发；只有用户明确要求提醒或定时任务时才安排自动化。

阅读时长按用户本次可用时间调整，不要求每读完一个小节就打卡。实际 API 调用前确认可用服务与预算。

## 章节知识点笔记

AI 默认整理和维护章节的重要知识点，供查阅与复习；用户按需补充重点或提出修正。笔记生成、用户认可笔记表述均不作为掌握证据，个人理解变化仍按“提问与学习记录”处理。

### 触发时机

- **首次安排阅读**：确定章节或小节的阅读范围后，在本次回复结束前生成对应范围的知识点笔记，无需用户另行要求。
- **继续、汇报或复习**：恢复当前学习范围时检查已有笔记；缺失或未覆盖本次范围的，自动补齐。已有内容可用且范围未变时直接复用。此规则也适用于启用本规则前已开始学习的章节。
- **内容修正**：答疑、诊断或核对资料时发现笔记有遗漏、错误，或相关原文已变化，核实后更新原笔记。用户要求“整理本章知识点”“补充本节笔记”等时，也直接执行。

自动整理由学习会话中的上述事件触发，不依赖固定口令；不在无对话时定时运行或监控资料。仅处理当前涉及或用户指定的范围，不批量整理尚未安排的课程。

### 整理与完成标准

1. **确定来源与覆盖范围**：定位实际资料及章节，读取已有笔记和本次指定的原文。记录资料名称、原文链接、章节或小节、可识别的版本及核对日期。无法读取时说明缺失范围与原因，保留已有内容；不得凭标题或模型记忆声称已完成原文整理。
2. **提炼重要知识点**：依据原文重点和学习目标，整理核心概念、关键机制或结论、适用条件与边界、知识点之间的关系。保留承载关键理解的例子、公式、推导或代码；详细程度以复习时能恢复主要思路为准，不机械凑条数或重写整章。各知识点附可定位的原文小节、页码或锚点；额外解释、类比和推论标注为“AI 补充”，引用外部资料时附来源。
3. **维护同一份章节笔记**：保存到 chapter-notes/<资料短名>/<章节短名>.md，例如 chapter-notes/hello-agents/ch03.md；无章节的独立文档以该文档为单位。同一资料的同一章跨阶段、跨模块共用一份，按小节逐步补齐，并在笔记开头列明已覆盖范围；部分覆盖不得标为整章完成。首次实际生成时再创建目录，用户补充的内容保留并注明来源。
4. **核验并交付**：对照原文检查本次范围的重要知识点、来源定位和补充标记，确认文件已保存，在回复中提供链接并简述新增或修正内容。资料读取不全时明确说明尚未完成的范围。整理笔记不改变 PROGRESS.md 中的阅读或掌握状态。

## 提问与学习记录

- 判断提问是否暴露重要概念缺口、重复误区、关键边界或可迁移的理解；有价值的内容才记录，避免逐条抄录聊天。
- 尚未解决或仅经教师解释的疑问记入 PROGRESS.md 的待解决问题，写明原文位置、问题与待验证点；讲解完成不代表用户已经掌握。
- 有真实理解、纠错证据或用户明确陈述的既有能力时，写入 learning-records/NNNN-slug.md，编号递增；采用简短结论与必要证据，按需附原文位置和复习提示。首次满足条件时再创建目录。
- 新问题与已有记录相同时优先补充同一记录；理解变化时保留修正缘由。长期学习偏好写入本文件，阅读活动和阶段状态放 PROGRESS.md。
- 重要理解或纠错验证后安排闭卷回忆或迁移复习，日期和结果记入 PROGRESS.md。

## 证据与范围

- 分开记录“已阅读（用户汇报）”和“理解已验证”。验收依据用户的解释、作答或练习证据，逐条以模块文档为准。
- 课程范围见 CURRICULUM.md；目标变更先与用户确认，再更新 README.md 中的学习目标。
- 涉及接口、依赖与协议时核对官方现行资料，记录练习实际版本。原文可能过时或表述过度时应指出并查证。
- 代码练习按需保存在对应模块目录内，记录运行方式、实际输出与版本；区分教师示例和用户独立完成的部分。
- 进度由学习会话依据证据更新，只在 PROGRESS.md 保存状态、验收统计与复习安排。
